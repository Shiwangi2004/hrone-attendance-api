# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Unconditionally returns `{"status": "ok"}` without checking if MongoDB is reachable. | Stopping the MongoDB daemon or providing an invalid connection still causes `/health` to return 200 OK instead of 503. | Added `client.admin.command("ping")` within a `try/except` block, raising `HTTPException(503, "Database unavailable")` on failure. |
| 2 | App initialization / global scope | No database indexes are created on startup. Relies solely on the default `_id` index. | Duplicate records can be created; all queries on a 100k dataset perform slow `COLLSCAN`s; `/admin/explain` fails index checks. | Implemented an `@asynccontextmanager` FastAPI `lifespan` handler that idempotently creates unique and composite query indexes at startup. |
| 3 | `create_employee` (lines 79-85) | Check-then-insert race condition (`find_one` followed by `insert_one`). | Simultaneous POST requests with the same `emp_code` both pass the check and create duplicates or throw unhandled 500 errors. | Enforced unique index on `emp_code`, removed check-then-insert, and caught `DuplicateKeyError` to return HTTP 409. |
| 4 | `create_employee` (line 82) | `created_at` stores naive local time and returns unformatted datetime instead of integer epoch milliseconds. | Response returns `"created_at": "2026-07-06T12:00:00"` instead of integer epoch ms (e.g. `1783312500000`), failing contract validation. | Stored UTC BSON datetime in MongoDB and converted to integer epoch milliseconds (`dt_to_epoch_ms`) in API response. |
| 5 | `EmployeeIn` (lines 53-61) | Missing schema validations: allows identical `shift_start` and `shift_end`, and lacks regex validation. | Client sending `shift_start="09:30"` and `shift_end="09:30"` receives 201 Created instead of 422 Unprocessable Entity. | Added Pydantic field patterns and a model validator asserting `shift_start != shift_end` and valid date formats. |
| 6 | `list_employees` (line 93) | Pagination skip formula is off by one: `skip = page * page_size`. Since `page >= 1`, page 1 skips records 0-19. | Requesting `GET /employees?page=1` returns items 21-40 instead of items 1-20; the first page of employees is never returned. | Fixed formula to `skip = (page - 1) * page_size`. |
| 7 | `list_employees` (line 94) | Collection total ignores filters: `total = db.employees.count_documents({})`. | Calling `GET /employees?department=QA` returns total headcount across all departments rather than QA, violating rule R10. | Updated total count query to reflect filters: `total = db.employees.count_documents(q)`. |
| 8 | `list_employees` (line 95) | Missing sort order: cursor does not sort by `emp_code`. | Employees are returned in arbitrary insertion order rather than sorted by `emp_code` ascending. | Added `.sort("emp_code", ASCENDING)` to the database cursor. |
| 9 | `punch_in` (lines 101, 113) | Missing check for non-existent employee before accessing `emp["shift_start"]`. | Punching in for an unknown `emp_code` raises an unhandled `TypeError` (NoneType subscript) returning 500 Internal Server Error. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 10 | `punch_in` (lines 104-118) | Check-then-insert race condition on `attendance_logs`. | Two concurrent punch-ins for the same employee on the same date both pass `find_one` and create duplicate logs or cause 500 errors. | Enforced compound unique index `[("emp_code", 1), ("date", 1)]` and caught `DuplicateKeyError` to return HTTP 409. |
| 11 | `punch_in` (lines 102-103) | Timestamp parsed in local server time, sub-second ms not truncated, and overnight shift calendar date ignored (R1). | Punch-in at 05:30 IST for shift 22:00-06:00 is assigned current day instead of previous day; milliseconds are not truncated. | Converted timestamp to IST, truncated to whole seconds (`ms // 1000 * 1000`), and adjusted attendance date by -1 day for overnight shifts. |
| 12 | `punch_in` (lines 119-121) | Injects forbidden `id` field and leaks raw BSON datetime. | Response contains `"id": "..."` and unformatted date objects, violating OpenAPI contract (`AttendanceRecord` has no id). | Removed `doc["id"]` and serialized `punch_in` and all timestamps to integer epoch milliseconds. |
| 13 | `compute_late_minutes` (lines 33-37) | Grace period logic bug (R2): `minutes = int(diff / 60); return minutes if minutes > 10 else 0`. | At 09:40:01 for a 09:30 shift, elapsed seconds = 601s, `minutes = 10`, `10 > 10` is False -> returns 0 instead of 10. | Changed condition to check elapsed seconds directly: `if diff_sec > 600: return diff_sec // 60 else 0`. |
| 14 | `compute_work_hours` (lines 40-41) | Uses Python standard `round()`, which applies Banker's Rounding (round half to even) instead of Half-Up (R4). | Float values ending in .XX5 round down to the nearest even number (e.g. 2.125 -> 2.12 instead of 2.13). | Replaced with `decimal.Decimal` using `ROUND_HALF_UP`: `Decimal(str(diff_sec / 3600)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 15 | `compute_overtime` (lines 44-47) | Returns `max(0, minutes)` without enforcing 30-min threshold (R3) and breaks on overnight shifts. | Punch-out 15 minutes after shift end gives 15 min overtime instead of 0; overnight shift end date is not advanced by +1 day. | Advanced shift end by +1 day if `shift_end <= shift_start`, and returned 0 unless difference is >= 1800 seconds (30 min). |
| 16 | `list_attendance` (lines 144-150) | In-memory loading `list(db.find(q))`, missing secondary sort, and no validation on `date_from > date_to`. | Crushes memory and CPU at 100k docs; `date_from > date_to` returns 200 with empty list instead of 422; secondary sort by `emp_code` missing. | Validated `date_from <= date_to` (422 if violated); used database cursor pagination `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`. |

### Also note anything you looked at and decided was **not** a defect, and why:
- **`load_dotenv()` at module load**: By default in `python-dotenv`, `load_dotenv()` does not override environment variables that are already set in the operating system or container runner. This conforms strictly to the requirement that injected environment variables (`MONGO_URI`, `MONGO_DB`) take precedence over a local `.env`.
- **Pydantic V2 BaseModels**: Using Pydantic V2 is standard, fast, and provides schema validation conforming with OpenAPI 3.0.3 requirements.
